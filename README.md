# gravity-inversion

C64 SID playroutines translated from 6502 machine code to C with the
[llvm-mos SDK](https://github.com/anarkiwi/docker-mos-llvm-sdk). Each translation issues
the same SID register writes, in the same order and play call, as the original up to the
tune's end.

Tunes and their data are not part of this repository: each tune's build fetches its
original (MD5-pinned) into `fixtures/`, which CI caches, and generates the C data header
from it byte-identical.

## Use

    docker build .            # lint, build, compare, test

or, with `mos-c64-clang` and `requirements-dev.txt` installed:

    make                      # tunes/*/build/*.prg
    make check                # compare each tune's SID writes against its original
    make test lint
    make readability          # readability defects of the generated C against budgets/

Each tune Makefile sets `GEN := 1` (with `PSID` and `CHECK_ARGS`) before including
`common.mk`, so `make` also builds `build/gen.prg` from the translation units in `build/gen`
(listed in `build/gen/units`: `<tune>_state.c`, `<tune>_init.c`, `<tune>_play.c`, `<tune>_shared.c`
when init and play share functions, and the host's `<tune>_host.c`) and `<tune>.h`, generated by
`tools/transliterate.py`: each unit's bitcode is linked into one module (`build/gen.bc`) that is
optimized as one file is. `make check` compares it with sidtrace too, the reference run
under the translation's overrun rule (`build/gen/overruns.json`: the sites the rule bounds). The
generated C depends on `build/lifter.stamp` (`tools/lifterstamp.py`: the installed lifter's
versions and native modules), so a pin or wheel change regenerates it.

## Tools

- [Disassembly and data flow](docs/disassembly.md): listings, decoding, per-instruction
  dependence and lift facts, from jennings, pysidtracker and deity-informant.
- [Diagnostic tools](docs/diagnostics.md): SID write comparison, coverage, data reads, value
  flow, residue, readability and size.

## Layout

| Path | Content |
|---|---|
| `tunes/<name>/` | one translation: C player, data generator, tests, notes |
| `c64/driver.c` | shared C64 driver: `tune_init`, then `frame_wait` / `tune_play` per call; `trap(k)` for the hand C |
| `common.mk` | shared make rules: fixtures, the C build; `GEN := 1` adds the generated translation |
| `tools/sidtrace.py` | SID write tracer and comparator per subtune: the PSID on pysidtracker's PSID machine (`oracle.boot_flat`), the C build on its power-on RAM, both on the header's SID model; `--overruns` applies the translation's overrun rule to the reference |
| `tools/disasm.py` | jennings coverage-driven disassembly listing of a PSID, computed transfers resolved through constant tables |
| `tools/survey.py` | rank tunes by the playroutine code they execute; branch outcome gaps |
| `tools/constructs.py` | validate `tunes/*/constructs.json`, each 6502 construct's hand-C form ([docs/constructs.md](docs/constructs.md)), against jennings coverage |
| `tools/opclass.py` | every opcode's roles in the lift procedure, from deity-informant's P-code |
| `tools/passes.py` | procedure graphs and loop kinds; the minimum number of lift passes ([docs/passes.md](docs/passes.md)) |
| `tools/footprint.py` | per-byte check of a hand translation's data against the original's data footprint from jennings coverage ([docs/footprint.md](docs/footprint.md)) |
| `tools/sizes.py` | PRG sizes beside the original 6502 player's ([docs/sizes.md](docs/sizes.md)) |
| `tools/eventlog.py` | every song data read of generated C, each an event, lookup, machine or table read by value flow (`tools/irflow.py`), with the state and SID writes after it: read sites in its LLVM IR (`tools/irmodule.py`, needs `clang`), logged natively ([docs/eventlog.md](docs/eventlog.md)) |
| `tools/flowgraph.py`, `tools/flowsegment.py`, `tools/condition.py` | value-flow graph of generated C (`tools/irflow.py`), its state machines, and per player family the lift and trace check ([docs/flowgraph.md](docs/flowgraph.md)) |
| `tools/orbitflow.py` | state machines of a PSID's play straight from the 6502 (jennings components), with cycle periods and tracker roles ([docs/flowgraph.md](docs/flowgraph.md#orbit-source)) |
| `tools/residue.py` | residue census: each site where generated C keeps the 6502's machine model, against `tests/residue_manifest.json` ([docs/residue.md](docs/residue.md)) |
| `tools/readability.py` | the generated C whose readability defects (wayward-eagle's census) `virtuous-cycles.toml` ratchets ([docs/readability.md](docs/readability.md)) |
| `tools/costs.py` | constructs in generated C that cost code size ([docs/costs.md](docs/costs.md)) |
| `tools/ablate.py` | where a generated translation's PRG bytes go: cumulative ablation of its C (AST model in `tools/cflow.py`) and a data accounting ([docs/ablate.md](docs/ablate.md)) |
| `tools/ghidra_ref.py`, `tools/ghidra/` | Ghidra headless reference decompilation of each target, seeded at the PSID's and the lifter's entries; image `docker/ghidra.Dockerfile` ([docs/ghidra_ref.md](docs/ghidra_ref.md)) |
| `tools/copies.py` | repeated playroutine code: unrolled copies with operand strides, JSR targets, fall-through entries |
| `tools/mutate.py` | mutation check: run a test command against source edits |
| `tools/transliterate.py` | PSID → translation units (or one `.c`) + `.h` with vagrant-moses' `cgen` (needs `mlir-opt` 22, `clang-format`) |
| `tools/relocate.py`, `tools/playtables.py`, `tools/pointers.py` | a PSID (play-only for one song, or of every song) with play's data moved off its code's pages by whole pages, each table bounded to its extent and padded with its last record, each reference rewritten at its source; proven by a protected run ([docs/relocate.md](docs/relocate.md)) |
| `tools/header.py` | shared header formatting and CLI of the tune data generators |
| `tools/tunetest.py` | checks the tunes' tests share: header values, traps, data footprint, generated C of patched songs |
