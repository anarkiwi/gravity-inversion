# Diagnostic tools

What to run to compare, trace and measure a translation, before writing a new tool.

| Question | Tool |
|---|---|
| Does a build issue the original's SID writes, in order, per call? | `tools/sidtrace.py PSID PRG (--frames N \| --hvsc ROOT \| --wrap LABELS LABEL) [--songs S] [--times T]`: the PSID runs on pysidtracker's PSID machine (`pysidtracker.oracle.boot_flat`: power-on RAM with the driver's `$0000-$03FE` clear and zeroed SID, the BASIC LOAD pointers, `$D418`, the PAL flag, `$01` at init's then play's bank), the PRG on that power-on RAM, both on the header's SID model; the first differing write is `pysidtracker.reglog.first_divergence`; each call's writes are `pysidtracker.emu.SidWriteLog(detail=False)` pairs, or with `trace_psid(..., detail=True)` its `(register, address read last, pc, value, cycle from the call's start)` records |
| Does a lift's overrun rule change what the original does? | `tools/sidtrace.py PSID PRG ... --overruns build/gen/overruns.json --song-data build/gen/song_data.json`: after the comparison, each site whose instruction accesses outside its object on the original played with no rule (`sidtrace.effects`: first frame, accesses, addresses) fails as `OVERRUN` where those addresses hold song data (`sidtrace.hidden`): its extent ends inside the data block. A rule replacing only code, state play writes or I/O is the tune never stopping; with no song data from the lifter (`null`) every such site fails. `--overruns` alone cannot see a short extent, since the reference takes the same sites. `tools/liftcheck.py` reports the same as `overruns on original` |
| What did the original do over its whole HVSC length? | the precomputed sidtrace captures beside each tune in the HVSC tree, `C64Music/<path>/<Tune>.<song>.csv.zst` (cycle, IRQ timing, chip, register, value; one song length per song): `pysidtracker.survey.oracle_frames(path, nframes=)` gives the per-frame register grid, `pysidtracker.oracle.grid_from_calls(calls)` the grid of a build's per-call writes, and `pysidtracker.oracle.aligned_match` compares grids. They are of the unmodified tune and are not re-run; a reference under a lift's overrun rule still needs `tools/sidtrace.py`. A new capture is `pysidtracker.oracle.run_sidtrace(tune, out, seconds=, song=, roms_dir=)`, `roms_dir` holding the real ROMs an RSID needs |
| How a tune modulates its SID registers over time | `tools/sidplot.py PSID OUT.png --hvsc ROOT [--song S] [--start F] [--frames N]`: each register's value at the end of each frame from the HVSC capture (frequency, pulse width and cutoff combined to 16, 12 and 11 bits), on a symlog axis |
| Which code a tune executes, and which branch outcomes it never takes | `tools/survey.py [--hvsc ROOT]`, `tools/disasm.py` ([disassembly.md](disassembly.md)) |
| Which song data a hand translation reads | `tools/footprint.py` ([footprint.md](footprint.md)) |
| Every song data read of generated C, with its state and SID writes | `tools/eventlog.py` ([eventlog.md](eventlog.md)) |
| Value flow and state machines of generated C | `tools/flowgraph.py`, `tools/flowsegment.py`, `tools/condition.py` ([flowgraph.md](flowgraph.md)) |
| State machines of a PSID's play, with no lift: roles, cycle periods, feed set, tracker roles | `tools/orbitflow.py PSID OUT [--song S]`: jennings components over the calls `cover_calls` proves cover play, explicit data and site taints, through `tools/flowsegment.py`'s pipeline ([flowgraph.md](flowgraph.md#orbit-source)) |
| Where generated C keeps the 6502's machine model | `tools/residue.py` ([residue.md](residue.md)) |
| Readability defects against budgets | `make readability`, `tools/readability.py` ([readability.md](readability.md)), `tools/fcomplex.py` ([fcomplex.md](fcomplex.md)) |
| Generated PRG bytes against budgets | `make prg`, `tools/prgsize.py` ([readability.md](readability.md#prg-bytes)) |
| Whether a PRG fits the C64 memory map | the link: llvm-mos' `c64/lib/link.ld` places every section, `.bss` and `.noinit` included, in `ram` (`$0801-$CFFF`) and its imaginary registers and zero-page sections in `$02-$8F` (`commodore.ld` region `zp`), the driver linked into the same image; `ld.lld` fails a build whose sections reach `$D000` (I/O) with `section '...' will not fit in region 'ram'`. The PRG carries its song data, so no original load area is resident. The soft stack grows down from `$D000` into the space above the sections, which the link does not bound; `make check` runs it |
| What costs code size | `tools/costs.py` ([costs.md](costs.md)), `tools/ablate.py` ([ablate.md](ablate.md)), `tools/sizes.py` ([sizes.md](sizes.md)) |
| Whether a test catches source edits | `tools/mutate.py` |
| Whether the lifter that generated the C changed | `tools/lifterstamp.py` |
